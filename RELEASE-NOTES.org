#+title: nvShift releases

* v0.5.0: document tabs, two-document layout, and shortcut help
Open document tabs explicitly while ordinary search continues replacing the
selected note. New-tab opening preserves the original note after arrow browsing.
Cmd/Ctrl+W now closes the active tab; the native window close button and File →
Hide window keep the application running with its workspace intact.

Two documents keeps a working note and reference side by side. Each pane chooses
Editor or Preview independently, with separate Find, scroll, and rendering state.
A new pane inherits the focused pane's mode; Editor + preview falls back to
Editor. Later opens keep the target pane's mode, and newly created notes start
in Editor. Right-click menus remain open after mouse release. Tab groups use an
active underline without visible L/R labels; ellipsis menus appear only when
tabs overflow.

The existing Split view is renamed Editor + preview and remains available for a
single document. Tabs, overflow menus, and layout controls occupy the existing
64-pixel toolbar without adding rows or pushing document content downward.

A lifebuoy beside Settings opens a platform-specific keyboard-shortcut reference,
also available through More or =?= outside editable controls. Question marks in
notes, search, forms, Vim, and shortcut recording keep their normal behavior.
The reference includes the configured global shortcut and restores focus when
closed. The Two documents label appears in the desktop toolbar before activation
and yields space to tabs while two-document mode is active; compact windows keep
the icon, and the empty reference pane explains the pane-switching shortcuts.

Tabs preserve cursor, folds, and Undo through switches and moves. Automatic .txt
syntax is fixed for an open document's lifetime, including across focus changes.
Closing/replacing and reopening detects again. Closing a tab saves safely and
never deletes the note; unresolved save errors and conflicts keep it available.

A full restart or notes-folder change starts fresh. Recovery drafts still open
as tabs when needed, and hiding the window or recovering the renderer preserves
the current workspace. Same-document dual views and persistent layout restoration
are not included in this version.

* v0.4.0: stable syntax and quick access
Asset cleanup is available from Settings → Notes folder as well as the File menu.
Automatic .txt syntax detection runs when opening a note and stays stable while
editing, saving, undoing, or receiving external changes. Reopen a note to detect
its latest contents, or choose its syntax beside the heading. The Automatic
label stays steady during typing and draft writes.

Quick access defaults to Ctrl+Alt+Space, or Control+Option+Space on macOS.
Profiles using the old default migrate once; custom and disabled shortcuts are
preserved. Settings records keyboard shortcuts and reports registration and the
last activation received. Failed replacements preserve the previous binding.
Wayland registrations remain awaiting verification until an activation arrives.

Physical shortcut delivery with another application focused remains a native
acceptance check on macOS, Windows, X11, and Wayland. Automated callback tests
verify nvShift's window and focus behavior, not OS key delivery.

* v0.2.0: automatic .txt syntax and heading folding
Use existing Markdown, Org, and plain-text =.txt= notes together without
renaming or converting them. nvShift detects syntax from each note's contents;
ambiguous or conflicting content stays readable as plain text.

- =New .txt note syntax= affects only future notes. The previous folder-wide
  choice becomes the creation default; existing notes detect independently.
- An optional per-note syntax control corrects guesses. Creation hints and
  overrides survive restart and in-app rename, without metadata in note files.
- Unsaved detection updates editing, headings, previews, Mermaid, and image
  insertion together, preserving selection, Undo, and Vim state.
- Asset cleanup checks all three interpretations of =.txt= references. Drafts
  are journaled before detection, and detector failures preserve editing/saving.
- Tab and gutter arrows toggle Markdown and Org heading sections in Editor
  and Split views. Vim supports Tab in Normal mode; Insert/Visual behavior,
  Space, Shift+Tab, and existing Vim commands are preserved. View → Folding
  provides Toggle heading and Expand all. Child folds survive closing parents,
  and source folding leaves the preview expanded.

Local macOS validation passes 245 tests, search and large-outline checks, development and
packaged Electron smoke, signatures, package contents, and license notices.
The release's linked Actions run records native hosted validation.

* First public release: v0.1.0
nvShift brings Notational Velocity's search-and-create workflow to ordinary local
plain-text, Markdown, and Org notes on macOS, Linux, and Windows. Earlier local
0.1.x builds were development milestones; the first public version is =v0.1.0=.

This release includes linked-directory notes, keyboard result browsing, safe
autosave and recovery, optional Vim editing, content-based headings, four themes,
image paste/drop with readable filenames, Mermaid preview, manual unused-asset
cleanup, and the copper Shift-key icon. New notes stay at the library root.

nvShift's own source and icons use BSD-3-Clause, copyright Chad Stovern.
Third-party licenses and Electron notices accompany each packaged application.

* Downloads and installation
Download packages from [[https://github.com/chadhs/nvShift/releases/latest][the latest release]] and compare their SHA-256 checksums.
GitHub's Source code archives contain source, not application installers.

| Platform | Packages | Checksum file |
|----------+----------+---------------|
| macOS Apple Silicon | arm64 DMG and ZIP | SHA256SUMS-darwin-arm64.txt |
| Linux x86_64 | AppImage and tar.gz | SHA256SUMS-linux-x64.txt |
| Windows Intel/AMD x64 | Per-user NSIS installer | SHA256SUMS-win32-x64.txt |

See [[file:README.org::*Install][Install]] for first-launch, update, and uninstall instructions.
Quit nvShift before updating: closing its window only hides it to the tray or
menu bar. Notes and preferences remain in place when replacing the application.

macOS packages are ad-hoc signed, without Developer ID signing or notarization.
Windows installers are unsigned. Intel Mac and native Windows ARM64 packages
are not supplied. There is no in-app updater.

* Release process
PRs and manual Desktop checks runs use read-only reusable desktop build jobs.
While the repository variable =RELEASES_ENABLED= is absent or false, main pushes
also run those checks and publish nothing. This allows the first public source
to pass all native jobs before publication is enabled.

After bootstrap, =RELEASES_ENABLED=true= enables automatic releases from trusted
main pushes and merged-PR fallback events. The first release uses the checked-in
version =0.1.0=. Each subsequent new source increments the highest stable tag's
minor version and resets patch to zero: =v0.2.0=, =v0.3.0=, and so on.
Documentation-only main changes also release.

The release workflow checks out the exact source SHA, requires it to belong to
main history, and stamps both package manifests for the build. Only after all
native tests and package checks pass does publishing verify exactly five
packages and three platform checksum files. It creates a versioned child commit
and tag marked =nvShift-Source:=, uploads into a draft, and publishes after every
upload verifies. The versioned child commit is not pushed back onto main.

Duplicate events and retries reuse the source's existing tag. Interrupted drafts
resume without replacing published releases or changing a newer latest release.
For recovery, rerun the failed Actions run, or dispatch =Release a minor version=
from main. Publishing alone receives repository write permission; build jobs
receive no signing or notarization credentials.

* Validation
Publication requires native macOS arm64, Linux x64, and Windows x64 build jobs,
the full test suite, the search benchmark, development and packaged-app smoke
checks, artifact inspection, and license verification. Windows checks also
exercise install, reinstall, and uninstall with preferences preserved.

Hosted run summaries are the evidence for native-runner results. Interactive
Wayland, physical global shortcuts, native folder-picker interaction, and native
Trash checks remain separate manual acceptance work until actually executed.
