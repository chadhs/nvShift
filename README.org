#+title: nvShift
#+subtitle: Notational Velocity for everyone.

[[file:build/icons/128x128.png]]

nvShift is a keyboard-driven desktop notes editor for macOS, Linux, and Windows.
Search your notes, create one from the same field, and start writing. Notes are
ordinary UTF-8 files in a folder you choose. Markdown and Org previews display
images and Mermaid diagrams. Vim editing is optional.

The project is an initial MVP. Native validation results and outstanding platform
checks are recorded in [[file:docs/VALIDATION.org][the validation record]].

* Run locally
Use Node 24 and npm. From this repository:
#+begin_src sh
npm ci
npm run dev
#+end_src
Choose a notes folder on first launch. nvShift remembers it. Existing files stay
in place; new notes are created at that folder's root. nvShift searches subfolders
but excludes hidden entries, =assets=, =node_modules=, and individual file links.

Directory symlinks and Windows directory junctions are followed, including links
to folders outside the selected library. Each real note appears once, with its
route through your library shown in results. Ordinary library paths take
precedence over linked aliases. Notes reached through links use this library's
creation preferences. Existing linked =.txt= notes detect syntax independently,
just like notes stored directly in the library.

Editing, renaming, and trashing a linked note affect the real file. New notes
still start in the library root. Links can be nested; cycles do not duplicate
notes. Broken or inaccessible links appear as library errors. If a link is
removed or points elsewhere while you are editing, nvShift preserves your draft
and pauses saving instead of sending the edit to a different file.

To open a particular library from the command line:
#+begin_src sh
npm start -- --library=/absolute/path/to/notes
#+end_src

* Install
Download [[https://github.com/chadhs/nvShift/releases/latest][the latest release]] and its platform's SHA-256 checksum file.
Downloaded builds need no Node.js, npm, or Emacs. GitHub's Source code archives
are not installers. The first public release is =v0.1.0=; earlier local version
numbers were development milestones.

** macOS, Apple Silicon
Quit existing copies of nvShift using its Quit action. Open the arm64 DMG,
drag =nvShift.app= into Applications, and eject the image. Launch the Applications
copy and choose a notes folder. The ZIP is an alternative to the DMG.

Packages are ad-hoc signed for bundle integrity and are not Developer-ID-signed
or notarized. Follow [[https://support.apple.com/en-us/102445][Apple's first-launch guidance]] when macOS asks you to approve
an app from an unidentified developer. Verify the download's checksum before
approving the app. Intel Mac packages are not included.

** Linux, x86_64
Download the AppImage or tar.gz and =SHA256SUMS-linux-x64.txt=. Verify the package
with =sha256sum=. Make the AppImage executable and run it. If FUSE 2 is unavailable,
use =--appimage-extract-and-run= or extract the tarball into a folder you own and
launch its =nvshift= executable as your normal user.

For native Wayland global-shortcut support, install the supplied
=com.chadhs.nvshift.desktop= launcher under =~/.local/share/applications/= and
set its =Exec= to the absolute path of your executable. Keep that reverse-DNS
filename. X11 and Wayland tray/portal availability depend on your desktop.
The library can also be selected with =nvshift --library=/absolute/path/to/notes=.

** Windows, Intel/AMD x64
Download =nvshift-VERSION-win-x64-setup.exe= and =SHA256SUMS-win32-x64.txt=.
Compare the checksum with PowerShell's =Get-FileHash -Algorithm SHA256=, then run
the installer as your normal user. It installs per-user without administrator
access. Open nvShift from Start and choose a notes folder. The installer is
unsigned; Windows may display an unknown-publisher or SmartScreen prompt.

To update on any platform, Quit nvShift and replace the app or run the new
Windows installer. Closing the window only hides it. Notes and preferences are
preserved. On Windows, uninstall through Settings → Apps. There is no in-app
updater; native Windows ARM64 packages are not included.

* Find or create a note
Type in the search field to find matching filenames and contents. Search is
case-insensitive, matches word prefixes, and requires every query term. Exact
titles rank first, followed by other title matches and content matches. An empty
search shows recently modified notes. Results show their relative folder when
needed to distinguish names.

Use Up and Down to highlight results and show each note while focus stays in
search. Browsing keeps the current Editor, Split, or Preview view; Enter opens
the highlighted note for editing and focuses its editor. Pending edits are
saved before browsing another note. A separate Create result creates a note
using the current query as its title. Highlighting Create does not create a file.
=Cmd/Ctrl+Enter= creates directly. Choose the extension beside the search field. Filename
validation and exclusive creation prevent replacing an existing note.

| Shortcut | Action |
|----------+--------|
| Cmd/Ctrl+L | Focus library search |
| Cmd/Ctrl+Enter | Create a note from the search text |
| Cmd/Ctrl+F | Find in the current document |
| Cmd/Ctrl+S | Save now |
| Cmd/Ctrl+Shift+P | Cycle Editor, Split, and Preview |
| Cmd/Ctrl+W | Save and hide the window |
| Cmd/Ctrl+Shift+Space | Raise nvShift and focus search, configurable |

Rename a note in its current folder, reveal it in your file manager, or move it
to the OS trash. Rename changes its filename only; links in other notes are not
rewritten. If the OS trash operation fails, nvShift reports the error and keeps
the note.

* File extension and content syntax
The default new-note extension is =.md=. Change it in Settings or choose another
extension when creating a note.

| Extension | Content syntax |
|-----------+----------------|
| .md, .markdown | Markdown |
| .org | Org |
| .txt | Detected from contents, with an optional per-note override |

Existing =.txt= files can mix Markdown, Org, and plain text in one folder.
Automatic detection recognizes Markdown headings, fenced blocks, links, and
images, and Org directives, blocks, links, and multi-level headings. Literal
code examples are ignored. Prose, ordinary lists, and a lone =* Heading= are
ambiguous; existing ambiguous files and files with conflicting evidence display
as plain text. The syntax control beside the view controls offers =Automatic=,
=Plain text=, =Markdown=, and =Org= when a guess needs correcting.

The folder's =New .txt note syntax= setting defaults to plain text and affects
only newly created =.txt= notes. A new note starts empty and remembers that
choice as its fallback until its contents identify a format; clear conflicting
evidence still falls back to plain text. Changing the preference affects future
notes only, so an existing collection needs no migration. Your previous =.txt=
setting becomes the creation default when upgrading.

Creation choices and manual overrides live in nvShift's application data and
survive restart and in-app rename. They are local to this nvShift profile and
are not synchronized with the notes folder. Existing notes on another device
are detected from their contents. No files are rewritten or renamed, and no
format metadata is inserted. Syntax changes preserve selection, undo, and Vim
state and apply to preview, headings, list editing, and image insertion.

Editor, Split, and Preview views share the current note. The editor starts in
source mode with wrapping, undo/redo, and document search. Preview follows
unsaved edits. Markdown and Org use the same bounded rendering implementation as
MarkupPreview; plain text displays literally.

The heading above the editor and the preview use an explicit document title
(Markdown YAML/TOML =title= or Org =#+TITLE:=), otherwise the first top-level H1,
otherwise the filename without its extension. Headings follow unsaved edits,
including in Editor view. An H1 used as the preview title is shown once; its
outline entry and links still work. Search results and rename keep using filenames.
Enable =Always use filename as heading= in Appearance to keep filename headings
and render all content headings in the preview. Plain-text notes always use filenames.

In Org notes, Enter continues bulleted and numbered lists with the same
indentation. Checkbox items continue unchecked. Enter on an empty item removes
its marker to end the list. This also works in Vim Insert mode and in =.txt=
notes configured as Org; literal source and example blocks keep ordinary newlines.

* Heading folding
In Editor and Split views, press =Tab= on a Markdown or Org heading to open or
close its section. The gutter arrows use the same ranges. Markdown supports
both =# ATX= and underlined Setext headings; Org supports star headings. Heading
examples inside literal/code blocks do not create sections. Plain-text notes
have no heading folding; =.txt= notes follow their detected or selected syntax.

In regular editing, =Tab= folds a heading when the selection is empty and the
heading has a body. Otherwise it indents the current or selected lines by one
level. =Shift+Tab= outdents those lines. Vim Insert mode also uses =Tab= and
=Shift+Tab= to indent and outdent lines.

With Vim enabled, =Tab= folding works in idle Normal mode only, with no pending
operator or key sequence. Elsewhere in idle Normal mode, =Tab= and =Shift+Tab=
do nothing. Visual mode, pending commands, and temporary Normal mode keep Vim's
Tab handling; unhandled Tab presses stay in the editor. Space, =zz=, and other
Vim commands keep their usual behavior; =za=, =zo=, and =zc= are not added.

=Cmd/Ctrl+L= returns to library search, where =Tab= and =Shift+Tab= navigate
controls. Search fields and dialogs retain normal Tab navigation.

Use View → Folding → Toggle heading from a section's body, or Expand all to
reveal the whole source. Closing a parent preserves folded child sections.
Search reveals hidden matches. Folds survive note switches, Editor/Split view
changes, appearance changes, and Vim toggles during the session. Restart,
external whole-document replacement, and syntax changes expand the source.
Folding leaves file contents and text Undo history intact. The rendered preview
remains expanded.

* Vim mode
Enable Vim mode in Settings. It starts off. Toggling it preserves text and undo
history. Normal, Insert, and Visual editing use CodeMirror's Vim extension.
=:w= saves the current note. Escape follows Vim semantics while editing;
=Cmd/Ctrl+L= returns to library search.

This is Vim-style editing, not an embedded Neovim process. Neovim plugins and
configuration files are not loaded.

* Images and diagrams
Paste an image into the editor or drop supported image files there. Clipboard
images are saved as PNG; dropped files keep their format. nvShift copies images
into the library's =assets/= directory using readable, unique filenames. For
example, =architecture diagram.png= becomes =architecture diagram-<uuid>.png=.
The original stem is made safe for supported filesystems and limited to 120
UTF-8 bytes. Repeated imports keep separate full UUIDs. Clipboard captures use
=clipboard-<uuid>.png=. Existing asset filenames and links are unchanged.

Image references resolve from the real note location, including external linked
notes. New references use relative paths when possible. Notes and assets on
different Windows drives use local file URLs.

Markdown syntax inserts an image link, Org inserts an Org file link, and plain
text inserts the path as text. Deleting a note or removing a link does not delete
its image assets. Use File → Find unused assets to review regular images directly
in the selected library's =assets/= folder and move explicitly selected images
to the OS Trash. Nothing is preselected; Select all unused excludes the separate
group referenced only by older recovery backups. An older note version may need
its image restored from Trash too.

Cleanup checks all supported library notes, including linked directories, saved
content, current buffers, and active recovery drafts. Undo references and recent
imports stay protected until nvShift restarts, including across library switches.
Incomplete scans block removal, and changed results require another scan. The
scan does not establish references from unrelated notes outside this library.
Symlinks, nested asset folders, and external image locations are not cleaned.
For =.txt= notes, cleanup checks all three syntax interpretations, regardless of
automatic detection or a manual override, so a format guess cannot hide a link.

Local image links and HTTP/HTTPS images display in the preview. Remote images
contact their hosts; requests omit cookies, authentication, and document
referrers. Local notes are not uploaded. Missing images show an explanation
without stopping editing. PNG, JPEG, GIF, WebP, and SVG are supported within the
renderer limits. SVG displays as an image without running scripts.

Markdown =mermaid= fences and Org =#+begin_src mermaid= blocks render locally.
No Mermaid CLI or Emacs installation is needed. Invalid or slow diagrams keep
their source available. Diagram code does not execute scripts or write files.

The inherited preview limits include 16 MiB per note, 8 MiB per image, a 32 MiB
image budget and 100 image links per note, and 20 Mermaid diagrams per note.
Other parser and diagram limits bound processing work. Large or unsupported
inputs produce an error rather than altering their source.

* Appearance
Appearance follows MarkupPreview's options and palettes:

| Setting | Choices | Default |
|---------+---------+---------|
| Mode | System, Light, Dark | System |
| Light theme | Default Light, Solarized Light | Default Light |
| Dark theme | Default Dark, Solarized Dark | Default Dark |
| Preview headings | Original serif, Sans-serif | Original serif |
| Preview width | Reading, Full width | Reading |
| Always use filename as heading | Off, On | Off |

Light and dark theme choices persist independently. System mode follows the
operating system. Colors apply to the title bar, search results, settings,
editor, syntax highlighting, preview, and diagrams. Heading font and reading
width affect the preview. Changing appearance preserves editor state. Zoom is
available through the View menu.

* Quick access and closing
The default global shortcut is =Cmd/Ctrl+Shift+Space=. Change it in Settings if
another application uses it. A registration failure is shown in the app; opening
nvShift again also raises its existing window.

Closing the window keeps nvShift running. The menu-bar or tray icon provides
Open, Settings, and Quit. Quit saves pending changes before exiting. Automatic
startup at login is not included.

On Linux Wayland, global shortcuts depend on the desktop's GlobalShortcuts
portal. The installed launcher uses =com.chadhs.nvshift.desktop= to match the
application's portal identity. The desktop may ask for shortcut permission or
provide its own shortcut settings. Use tray access or relaunch the app when a
shortcut is unavailable. Xvfb CI checks do not substitute for a real Wayland
session check.

* Saving, external editors, and recovery
nvShift autosaves after a short typing pause and flushes changes when switching
notes, hiding the window, or quitting. Save status distinguishes pending saves,
saved content, conflicts, and errors. Existing UTF-8 BOM and newline conventions
are preserved. Invalid UTF-8 and over-limit files are rejected without changes.

You can use another editor on the same files. Clean notes reload outside changes.
If an outside edit conflicts with an unsaved buffer, nvShift pauses autosave and
preserves both versions. Keep both saves the editor version as a separate note;
Use disk reloads the disk version while retaining the draft in recovery storage.
Outside deletion does not discard unsaved text.

Recovery snapshots live in nvShift's application-data directory, separate from
the notes folder and MarkupPreview's preferences. Journaled unsaved drafts are
checked on restart. Abrupt process or machine failure can lose edits that have
not reached the journal. Recovery is not a replacement for backing up the notes
folder. Existing cloud-folder synchronization remains the responsibility of its
provider; nvShift has no custom sync service.

* Development and local packages
#+begin_src sh
npm test                 # Unit and integration checks
npm run build            # Renderer and standalone analysis bundles
npm run check            # Tests and build
npm run test:benchmark   # Search benchmark against 10,000 notes
npm run test:benchmark:syntax # Worker detection latency and a 6 MiB stress case
npm run test:smoke       # Electron desktop smoke checks
npm run test:package:mac # Extract ZIP, run packaged smoke, verify DMG and signatures
npm run icons            # Rebuild original app and tray icon assets
npm run notices          # Validate runtime licenses and regenerate notices
npm run notices -- --check # Verify that generated notices are current
npm run pack             # Unpacked application for local checks
npm run dist:mac          # Ad-hoc-signed DMG and ZIP
npm run dist:linux        # AppImage and tar.gz
npm run dist:win          # Unsigned per-user Windows NSIS installer
npm run checksums        # SHA-256 checksums for packages in release/
#+end_src

Build native packages and run native smoke tests on each target platform.
On Linux, run desktop smoke checks with =xvfb-run --auto-servernum= when no display
is available. =NVSHIFT_EXECUTABLE= lets the smoke runner target a packaged
executable. =scripts/check-package.mjs= checks packaged identity, required files,
and license notices. The Windows installer lifecycle helper is restricted to a
disposable GitHub Actions runner.

Reusable workflows under =.github/workflows/= test and package macOS arm64,
Linux x64, and Windows x64 builds. PR/manual checks are read-only. While the
repository variable =RELEASES_ENABLED= is disabled, main pushes run native checks
without publishing. After the bootstrap checks pass, enabling that variable and
dispatching the release workflow publishes =v0.1.0=. Later new main sources
automatically publish minor versions: =v0.2.0=, =v0.3.0=, and so on.

Only publishing receives repository write permission. All native builds,
package checks, and verified checksums must pass before a draft is published.
See [[file:RELEASE-NOTES.org][release information]] for retries, installation, and release details.
Hosted workflow summaries establish native-runner results. Interactive Wayland,
physical shortcuts, native picker interactions, and native Trash remain manual
checks until actually executed; package configuration alone does not validate them.

Developer signing certificates, macOS notarization, Windows code signing,
automatic updates, TextBundle/TextPack, rich-text editing, and full Emacs Org
functionality are outside this MVP.
